# Codex 额度任务栏贴边浮层设计

**日期：** 2026-08-02  
**状态：** 用户已确认，待独立规格审查  
**实施方式：** 在现有仓库和解决方案中增量迁移；取代正式产品中的 Explorer/XAML 注入显示路径，不改变已经确认的 Codex 额度语义、Liquid Capsule 视觉或详情卡交互。

## 1. 背景与决策

实时兼容性探针已证明当前系统中的 Windhawk `Windows 11 Taskbar Styler` 会占用并保护 XAML Diagnostics。该模组在 `alert` 模式下同步拦截其他消费者，导致桥接工作线程在初始化阶段等待确认框，随后触发 Ready 和清理超时。XAML Diagnostics 同时只能由一个消费者可靠使用，因此正式产品不应绕过该保护，也不应自动修改 Windhawk 设置。

正式产品在当前代码库内改为宿主进程拥有的任务栏贴边浮层。浮层在视觉上紧贴任务栏，但不进入 Explorer 进程、不修改任务栏 XAML 树，也不依赖 Windhawk。这不是新建另一个仓库或推倒重做：现有解决方案、Core 项目、兼容性证据模型、构建脚本、安全扫描、测试框架和已经确认的产品交互继续复用。现有兼容性探针保留为独立的历史诊断工具，不由正式应用启动，也不进入正式应用发布包。

当前仓库尚没有面向用户的长期运行 Host 可执行程序，只有 Core、BridgeControl、原生桥接和兼容性探针。因此必须在同一解决方案内新增 `CodexQuotaTaskbar.Host` 作为正式入口；“新增 Host 项目”只是把现有基础补成可运行产品，不代表另起炉灶。

## 2. 目标与非目标

### 2.1 目标

- 在每个选定显示器的任务栏工作区一侧显示 190 × 36 DIP 的 iOS 风格 Liquid Capsule。
- 保留原方案的双额度条、悬停提示、详情卡、右键菜单、低额度状态与无障碍行为。
- 与 Windhawk 及其任务栏样式模组共存。
- 支持多显示器、混合 DPI、四种任务栏方向、自动隐藏、Explorer 重建和全屏应用。
- 使用 Codex 官方 App Server 读取当前登录账号的 ChatGPT Codex 额度，不直接读取任何凭据文件。
- 正式应用退出后不留下浮层、托盘图标或由其启动的 Codex 子进程。

### 2.2 非目标

- 不在 Explorer 内嵌控件，不修改或替换任务栏 XAML 元素。
- 不绕过、关闭或改写 Windhawk 的 XAML Diagnostics 保护。
- 不自动登录 Codex，不解析 `auth.json`、浏览器 Cookie 或其他账号凭据。
- 不在浮层中执行模型请求、任意命令、脚本或网页内容。
- 不保证在独占全屏、锁屏或任务栏完全隐藏时继续显示。

## 3. 总体架构

正式产品新增 `CodexQuotaTaskbar.Host`，它是唯一长期运行的产品进程。Host 内部包含以下边界清晰的组件：

1. `CodexRateLimitProvider`：启动并管理本机 Codex App Server 子进程，获取和规范化额度。
2. `QuotaStateStore`：在内存中保存最后一次有效快照、数据新鲜度和错误状态。
3. `TaskbarTopologySource`：只读枚举任务栏窗口、显示器、工作区、DPI、任务栏方向与可见性。
4. `OverlayCoordinator`：为每个选定显示器创建、移动、隐藏或销毁一个胶囊浮层。
5. `QuotaCapsuleWindow`：渲染 190 × 36 DIP Liquid Capsule，并处理悬停、主键和右键输入。
6. `QuotaPopoverWindow`：应用拥有的 300 DIP 详情卡；显式点击后可获取焦点并支持键盘操作。
7. `TrayController` 与 `SettingsStore`：提供托盘菜单、显示器选择、开机启动和退出控制。

额度状态在同一进程内通过不可变快照传递给胶囊和详情卡。正式产品不再需要 Explorer 桥接 DLL、远程加载、状态文件点击命令或注入日志。

### 3.1 现有代码的增量复用

| 当前资产 | 增量处理 |
|---|---|
| `CodexQuotaTaskbar.slnx`、统一构建属性和版本文件 | 原样保留，将 Host 与新增测试加入现有解决方案 |
| `CodexQuotaTaskbar.Core` | 原样保留现有兼容性模型，并在该项目中新增额度规范化、状态和纯定位逻辑 |
| 兼容性证据、报告和安全失败分类 | 复用为诊断与发布验证依据，不再作为浮层启动前的注入门禁 |
| `CodexQuotaTaskbar.CompatibilityProbe` | 保留为单独构建的开发诊断工具，正式 Host 不引用它 |
| `CodexQuotaTaskbar.BridgeControl` 与 `src/native/taskbar-bridge` | 不删除用户已有工作；冻结为诊断路径，正式 Host 和正式发布包不依赖它们 |
| `build.ps1`、`build/verify.ps1` 和安全扫描 | 在现有脚本上增加 Host 构建、浮层测试和“正式包零注入载荷”断言 |
| 现有 xUnit、CTest 与敏感边界自测 | 保留并扩展；原生诊断测试继续独立运行，新增 Host/Overlay/Provider 测试 |
| 已确认的 Liquid Capsule 规格 | 保留尺寸、颜色、状态和交互；将渲染从原生 Explorer XAML 等价迁移到 Host WPF |

原生 `probe_capsule` 的 Windows.UI.Xaml 对象不能直接搬到进程外 WPF 窗口中复用，但它锁定的布局常量、视觉规则、状态分类和相应测试期望可以逐项迁移。迁移后用 WPF 渲染快照与既有视觉清单做等价验证。

## 4. 浮层窗口与任务栏定位

### 4.1 窗口属性

每个胶囊使用独立的透明 WPF 工具窗口：

- 不显示在 Alt+Tab 或任务栏中；
- 默认不激活、不抢夺当前前台窗口焦点；
- 接收鼠标悬停、主键和右键输入；
- 背景刷新、显示器变化和自动重定位不得激活窗口；
- 仅用户主键打开详情卡时，详情卡可正常激活，以支持 `Esc` 和键盘导航。

胶囊 HWND 使用 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，并仅在任务栏可见且目标显示器没有真正全屏窗口时保持 topmost。它不得通过周期性强制置顶压过系统安全界面；会话锁定时立即隐藏。详情卡是独立的 Host-owned 窗口，仅由显式点击激活。

实现时使用受测的 Win32 扩展样式和 WPF HWND 生命周期适配。样式或 Z-order 设置失败必须关闭该实例并报告降级状态，不创建行为不确定的窗口。

### 4.2 锚点规则

胶囊名义尺寸为 190 × 36 DIP。默认间距为任务栏边缘 8 DIP、显示器工作区右侧 12 DIP：

- 底部任务栏：放在任务栏上方，靠工作区右侧；
- 顶部任务栏：放在任务栏下方，靠工作区右侧；
- 左侧任务栏：放在任务栏右侧，靠工作区底部；
- 右侧任务栏：放在任务栏左侧，靠工作区底部。

应用清单声明 Per-Monitor-V2 DPI awareness。所有 DIP 在目标显示器有效 DPI 下转换为物理像素，最终矩形必须完整位于该显示器工作区。负坐标显示器和非矩形排列不得被归一化到主屏。胶囊 HWND 收到 `WM_DPICHANGED` 时先采用系统建议矩形，再由 `OverlayCoordinator` 使用新 DPI 和最新任务栏几何做一次防抖重算；跨屏移动不得继续使用原显示器的 WPF 缩放值。

### 4.3 拓扑与显隐

`TaskbarTopologySource` 使用窗口类、窗口矩形、显示器信息和系统 DPI API，只读识别主任务栏与副任务栏。它不打开 Explorer 写权限，也不读取 Explorer 内存。

以下事件触发防抖重算：显示器增删、分辨率或缩放变化、工作区变化、任务栏窗口创建/销毁/移动、Explorer 重建、设置中的显示器范围变化。

当目标任务栏不可见、自动隐藏且未展开、会话锁定，或目标显示器存在真正全屏的前台窗口时，胶囊隐藏；条件解除后恢复。真正全屏要求前台顶层窗口属于目标显示器，未被 DWM cloaked，且其扩展框架边界在小容差内覆盖完整显示器边界（包括任务栏占用区域）。仅覆盖工作区的普通最大化窗口不视为全屏。Explorer、桌面窗口和 Host 自身窗口不参与该判定。显隐和移动使用减少动画设置，避免在系统要求减少动态效果时播放非必要过渡。

### 4.4 多显示器设置

默认在每块具有可识别任务栏的显示器上显示一个胶囊。设置提供“全部任务栏”和“仅主任务栏”。详情卡始终锚定到被点击的胶囊，并限制在同一显示器工作区内。

## 5. 视觉与交互

### 5.1 Liquid Capsule

保持原设计：

- 190 × 36 DIP，18 DIP 圆角；
- 深色半透明玻璃壳、细浅色边框、克制的内高光和阴影；
- 左侧 25 DIP Codex 圆形标识；
- 右侧两行额度：标签、4 DIP 圆角轨道和右对齐剩余百分比；
- 剩余量至少 30% 使用冷色，10%–29% 使用琥珀色，低于 10% 使用红色；
- 不可用状态使用中性色，过期状态降低饱和度，并同时显示文字或图标，不只依靠颜色。

透明效果关闭或处于高对比度模式时，使用不透明系统兼容表面。100%–200% Windows 缩放下文字和进度条必须保持清晰。

### 5.2 指针与键盘

- 悬停：显示剩余额度、重置时间和数据新鲜度提示，不打开详情卡。
- 主键：切换详情卡；第二次点击关闭。
- 右键：打开“立即刷新、打开 Codex、设置、开机启动、退出”菜单。
- 双击：不绑定动作。
- 详情卡在外部点击、`Esc`、第二次胶囊点击、任务栏重建或显示器拓扑变化时关闭。

### 5.3 详情卡

详情卡宽 300 DIP，显示所有可识别额度窗口、剩余百分比、本地化重置时间、脱敏账号/套餐（若官方响应提供）、新鲜度、立即刷新和打开 Codex。后台刷新不得重新打开或激活已关闭的详情卡。

## 6. Codex 数据路径

Host 启动本机已安装的 `codex app-server --listen stdio://`，使用官方 JSONL-over-stdio 协议。启动流程为：

1. 完成 App Server 初始化握手和能力探测；
2. 调用 `account/read` 确认认证模式；
3. 调用 `account/rateLimits/read` 获取完整额度快照；
4. 监听 `account/rateLimits/updated`，将其视为失效信号并防抖执行完整读取；
5. 监听 `account/updated`，立即清除前一账号数据并使用新的账号代次重新读取。

官方 App Server 文档目前仍将该命令标为实验接口，因此版本号本身不能作为兼容依据。每次启动都验证初始化、账号和额度方法及必要字段；未知附加字段可以忽略，缺失或类型错误的必要字段必须拒绝。

`usedPercent` 必须是 0–100 的有限值，显示值为 `100 - usedPercent`。`resetsAt` 按 Unix 秒解释并转换为 Windows 当前时区。`rateLimits` 用作向后兼容单桶视图；存在 `rateLimitsByLimitId` 时可显示多个计量桶。通知中的稀疏字段不得直接覆盖完整快照。

紧凑胶囊固定为两行，采用确定性选择规则：优先选择 `rateLimitsByLimitId["codex"]`，不存在时使用向后兼容的 `rateLimits`；将该桶中通过验证的 primary 和 secondary 窗口按 `windowDurationMins` 升序排列，同持续时间保持 primary 在前，只显示前两项。只有一项时第二行显示中性的不可用占位；没有有效项时进入不可用状态。其他 `limitId` 和超出两项的窗口只在详情卡中显示，详情卡按 `codex` 优先、其余 `limitId` 序号比较、窗口持续时间升序排列，并用“更多额度”分组承载溢出内容。

应用不发起登录流程。未登录时提示通过 Codex 登录；API Key、Bedrock 等不提供 ChatGPT 额度的认证模式显示“当前登录方式不提供 ChatGPT 额度”。

## 7. 状态、错误与恢复

`QuotaStateStore` 只接受完整且通过验证的新快照。失败时保留最后一次有效快照并标记新鲜度：

| 状态 | 胶囊 | 详情卡/操作 |
|---|---|---|
| 正常 | 双额度条与剩余百分比 | 显示重置时间和刷新 |
| 数据过期 | 降低饱和度并显示过期标记 | 显示最后更新时间，可手动刷新 |
| Codex 未安装 | 中性不可用状态 | 提示安装或定位 Codex |
| 未登录 | 中性登录状态 | 提示通过 Codex 登录 |
| 登录方式无额度 | 中性说明状态 | 说明当前认证模式不提供 ChatGPT 额度 |
| 协议不兼容 | 中性更新状态 | 提示更新 Codex 或本应用 |
| 子进程断开 | 保留最后有效值并标记过期 | 指数退避重连，可手动刷新 |
| 无任务栏锚点 | 不显示该实例 | 托盘菜单保持可用并说明原因 |

重连必须有上限和抖动，避免紧密循环。退出、会话结束或设置禁用显示时取消挂起读取，关闭所有 UI，然后请求 App Server 子进程正常退出；超时后仅终止由当前 Host 创建且身份仍匹配的子进程。

## 8. 安全与隐私边界

- 正式 Host 不引用 `CodexQuotaTaskbar.BridgeControl`，不嵌入原生桥接 DLL，不调用 `VirtualAllocEx`、`WriteProcessMemory`、`CreateRemoteThread` 或远程 `FreeLibrary`。
- 正式发布验证必须证明产品包中不存在兼容性探针和桥接载荷；诊断工具单独构建和分发。
- Host 只通过公开窗口/显示器 API 获取任务栏几何，不读取 Explorer 内存或修改其状态。
- Provider 只与其创建的 Codex App Server 子进程通信，不读取 `auth.json`、Cookie、令牌缓存或任意账号文件。
- 日志和导出诊断不包含账号、完整路径、环境变量、原始 App Server 消息或命令行内容。
- 设置和派生额度值写入固定的当前用户应用数据目录，使用原子替换；不持久化访问令牌。
- 该设计不声称能防御已以同一用户身份运行的恶意进程。

## 9. 测试策略

### 9.1 纯逻辑测试

- 四种任务栏方向、负坐标、多显示器排列、100%–200% DPI 和边界夹取；
- 自动隐藏、全屏、任务栏消失/重建和防抖重定位；
- 全部任务栏/仅主任务栏选择；
- 剩余百分比、额度桶选择、重置时间和新鲜度状态；
- 无效、截断、超大、未知版本和稀疏 App Server 消息；
- 账号切换时的代次隔离，拒绝前一账号迟到响应。

### 9.2 UI 与无障碍测试

- 锁定 190 × 36 DIP、18 DIP 圆角、25 DIP 标识和 4 DIP 轨道；
- 正常、低额度、过期、不可用、高对比度和透明效果关闭状态；
- 胶囊不进入 Alt+Tab、不抢焦点，详情卡仅在显式点击后激活；
- UI Automation 名称、百分比值、Invoke 模式、键盘顺序和 `Esc`；
- 减少动画时不播放非必要过渡。

### 9.3 边界与发布测试

- 正式 Host 依赖图和发布包不得包含 BridgeControl、兼容性探针或原生桥接 DLL；
- 敏感 API/字符串扫描证明正式 Host 不含 Explorer 注入路径；
- 文件访问审计证明 Host 不打开凭据文件；
- 使用脱敏的官方协议样本完成 Provider 合同测试，不使用真实账号数据；
- 启动/退出循环、显示器拓扑变化和至少 30 分钟快照更新稳定性测试。

### 9.4 实机验收

实机验收只启动独立浮层，不运行实时注入探针，也不重启 Explorer。检查：

- 当前 Windhawk 模组保持启用时，胶囊正常显示和交互；
- 主屏和副屏定位正确，不遮挡任务栏或全屏内容；
- 背景刷新不抢焦点；
- 详情卡和右键菜单行为正确；
- 退出后浮层、托盘图标和 Host 创建的 Codex 子进程全部消失。

## 10. 迁移与交付边界

实现直接在现有解决方案中进行，不复制仓库。第一步给现有 `CodexQuotaTaskbar.Core` 增加纯额度状态与浮层定位模型，同时给解决方案加入 Host 和对应测试项目；第二步把原生胶囊中已经确认的视觉常量和状态规则等价迁移到 WPF；第三步在现有构建与安全脚本上增加 Host 发布目标。原计划中 Explorer-side renderer、状态文件点击命令、注入激活日志和桥接生命周期不进入正式 Host 的运行依赖，但相关源代码和测试不会在迁移时被破坏或删除。

第一阶段交付一个使用脱敏模拟额度的可运行浮层，先验证位置、视觉、输入和退出。第二阶段接入 Codex App Server 与真实额度。第三阶段补齐设置、开机启动、通知和发布包。每一阶段都必须维持“正式产品零 Explorer 注入”的发布断言。

## 11. 验收标准

设计完成的产品必须同时满足：

1. Windhawk `Windows 11 Taskbar Styler` 保持启用时可启动和使用；
2. 正式产品从未将 DLL 或代码加载到 Explorer；
3. 胶囊视觉与原确认方案一致，并位于任务栏工作区一侧；
4. 多显示器、DPI、自动隐藏、全屏和 Explorer 重建行为可预测；
5. 额度只来自官方 Codex App Server，且显示“剩余”语义；
6. 不读取凭据文件，不记录敏感账号数据；
7. 退出后不留下 UI 或由 Host 创建的子进程；
8. 自动测试、发布边界测试和实机验收全部通过。
