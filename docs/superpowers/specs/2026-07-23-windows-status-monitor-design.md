# Windows 状态监控原生应用设计

## 目标

将现有 State 风格网页原型实现为 Windows 原生托盘应用：托盘单击后在通知区域附近弹出半透明状态面板，实时展示电脑性能与安全的系统快捷操作。

## 范围

第一版支持：

- 托盘常驻、单击显示或收起面板、右键退出。
- 每 2 秒更新 CPU、内存、C 盘空间、网络收发速率、局域网 IP、开机时长与 GPU 使用率。
- CPU/GPU 温度仅在传感器读取成功时显示；无数据时显示 `—`。
- 内存压力阈值通知；手动“优化内存”使用温和模式。
- 快捷操作：任务管理器、Windows 设置、锁定、截图工具、深色模式、夜间模式和存储设置。
- State 风格的浅色毛玻璃卡片布局，但所有文案、指标和快捷操作均采用 Windows 语义。

第一版不支持：

- 风扇控制、合盖不休眠、macOS 专属功能。
- 未公开 Native API 的待机列表清空。
- 对全部进程进行强制工作集回收。
- 安装器、自动更新与开机自启动。

## 技术方案

使用 .NET 9 WPF（`net9.0-windows`）和 WinForms `NotifyIcon` 实现 Windows 托盘行为。WPF 负责无边框面板、Acrylic/Mica 近似的玻璃材质和数据绑定；托盘图标通过右键菜单提供显式退出入口。

应用分为四个边界清晰的模块：

1. `MetricsService`：以固定间隔聚合指标。
2. `MetricsProviders`：读取 Windows API、BCL 网络与磁盘指标；温度采用可选传感器适配器。
3. `TrayController`：管理 `NotifyIcon`、定位面板、显示/隐藏和退出。
4. `StatusPanel`：显示状态卡片、通知和快捷操作。

## 指标数据

| 指标 | 实现 | 无数据时 |
| --- | --- | --- |
| CPU | `GetSystemTimes` 两次采样差值 | `—` |
| 内存 | `GlobalMemoryStatusEx` | `—` |
| C 盘 | `DriveInfo` | `—` |
| 网络 | `NetworkInterface` 的收发字节差值 | `—` |
| IP | 有默认网关的已连接网卡 | `未连接` |
| 开机时长 | `Environment.TickCount64` | `—` |
| GPU 活跃度 | Windows GPU Engine 性能计数器所有实例中的最高有效值，失败时降级 | `—` |
| CPU/GPU 温度 | 可选 LibreHardwareMonitor 适配器 | `—` |

## 内存优化原则

Windows 会在需要时自行回收文件缓存与待机页，因此不能把“已用内存降低”当作固定的性能提升指标。第一版只允许用户手动发起温和优化：对当前用户可访问且非关键的候选进程调用公开的 `K32EmptyWorkingSet`，记录尝试结果并在 UI 中描述为“整理工作集”，不宣称“清空全部内存”。

第一版的内存提醒阈值固定为“可用物理内存低于总内存的 15%”，无需新增设置窗口。每 15 分钟最多发送一次提醒；当可用内存回升至 20% 以上后，提醒计时重置。自动策略只发送提醒，不自动执行工作集整理。深度缓存清理需要管理员权限且风险较高，留给后续高级功能单独设计。

GPU Engine 计数器按进程和引擎分别上报，多个实例相加可能超过 100%。因此第一版卡片名称为“GPU 活跃度”，显示所有有效实例中的最高值，不把它误称为全机 GPU 总负载，也不在第一版区分多张显卡。

## 快捷操作

每项操作必须明确反馈成功、失败或系统不支持。所有操作使用 Windows 自身命令或 URI，而不是静默修改注册表。

- 任务管理器：启动 `taskmgr.exe`。
- Windows 设置：启动 `ms-settings:`。
- 锁定电脑：调用 `LockWorkStation`。
- 截图工具：启动 `ms-screenclip:`。
- 深色模式和夜间模式：第一版打开相应设置页面，而不直接改注册表。
- 存储设置：启动 `ms-settings:storagesense`。

## 可验证的验收条件

1. 构建产生可启动的 Windows 可执行程序。
2. 托盘图标单击可显示/隐藏面板，右键存在退出操作。
3. 面板在真实机器上刷新至少 CPU、内存、C 盘、网络和开机时长。
4. 温度或 GPU 不可用时显示 `—`，不报错、不伪造数据。
5. “优化内存”不会尝试终止进程、清空待机列表或请求管理员权限。
6. 关键数据计算和快捷操作映射均具备自动化测试。
